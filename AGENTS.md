# Аким на 5 часов — правила для AI-агентов

## Проект
AI-симулятор управления городом. Пользователь выбирает ровно 5 мер из 14 при бюджете 100, система считает Astana Quality of Life Score, AI объясняет результат. AI НЕ считает числа, только объясняет готовые результаты движка.

Стек: Python 3.11+, FastAPI, uvicorn, openai SDK, pytest. Фронтенд: статические HTML/CSS/JS без сборки, отдаются FastAPI.
Запуск: `pip install -r requirements.txt && uvicorn api.main:app --reload` → http://localhost:8000

## Формула
1. I'_dk = clip(I_dk + Σ эффект_mk × (8 − L_m)/8 + синергии, 0, 100). Мера типа C действует на все 5 районов.
2. D_d = Σ w_k × I'_dk
3. D_avg = Σ pop_d × D_d
4. Score = 0.7 × D_avg + 0.3 × min(D_d) − 1.0 × N_crit, где N_crit — число пар «район × показатель» со значением строго < 40 после эффектов.

Контрольные числа (обязательные тесты):
- без мер: Score = 52.55768 (D_avg 56.8624, N_crit 2)
- M7 Нура, M8 Нура, M10 Нура, M12 город, M5 Сарыарка: Score = 56.54307, стоимость 95
- M9, M11, M10, M12, M4 — стоимость 61, валиден

## Правила валидации (ошибки на русском)
1. Сумма стоимостей ≤ 100.
2. Ровно 5 мер.
3. Без повторов.
4. Для типа R район обязателен и из списка; для типа C район = null.
5. Не более 2 мер из одного направления.
6. Несовместимости запрещены.
7. Невалидный набор не получает Score, возвращается список причин.
8. Порядок мер не важен.

## Контракт между модулями
Решение: `{"measure_id": "M7", "district": "Нура"}`, для городских мер `"district": null`.

engine (Агент 1):
- `load_data() -> dict`
- `validate(decisions: list[dict], event_id: str | None = None) -> dict` → `{"valid": bool, "errors": [str], "total_cost": int, "budget": int, "budget_left": int}`
- `simulate(decisions: list[dict], event_id: str | None = None) -> dict` → результат ниже (без валидации внутри; `[]` = базовый сценарий)
- `optimize(top: int = 5, event_id: str | None = None) -> list[dict]` → `[{"decisions": [...], "score": float, "total_cost": int}]`, лучшие валидные наборы, считать ≤ 10 секунд, результат кэшировать отдельно для каждого события
- `list_events() -> list[dict]` → все события
- `get_event(event_id: str) -> dict` → одно событие, неизвестный id → `ValueError` с текстом на русском

Результат simulate:
```json
{
  "total_cost": 95, "budget_left": 5,
  "base_score": 52.56, "score": 56.54, "delta": 3.98,
  "d_avg": 0.0, "min_district": {"name": "Нура", "score": 0.0},
  "n_crit": 0, "critical": [{"district": "Нура", "indicator": "S1", "value": 38.0}],
  "districts": [{"name": "Есиль", "population": 0.27, "before": {"T1": 45}, "after": {"T1": 45}, "score_before": 62.99, "score_after": 62.99}],
  "contributions": [{"measure_id": "M7", "district": "Нура", "cost": 24, "delta_score": 1.2}],
  "synergies": [{"pair": ["M10", "M12"], "district": "Нура", "indicator": "B1", "bonus": 2}]
}
```
contributions.delta_score = Score(все меры) − Score(все меры без этой). Внутри считать без округления, в API округлять до 2 знаков.

### События (опционально)
Событие — неожиданная городская ситуация, требующая перераспределения бюджета. Данные в `engine/events.json`, 5 событий EV1…EV5:
```json
{"id": "EV1", "name": "Прорыв теплосети", "description": "...", "district": "Алматы", "effects": {"C1": -18, "C2": -8}, "budget_penalty": 12}
```
`district: null` — событие действует на все районы. `effects` — отрицательные сдвиги показателей, применяются к исходным значениям до мер и НЕ масштабируются лагом. `budget_penalty` (5–15) уходит на ликвидацию, поэтому доступный бюджет = 100 − budget_penalty.

`event_id` везде необязателен: без него поведение и числа прежние. При событии `validate` возвращает уменьшенный `budget`, а текст ошибки о перерасходе называет событие; `simulate` считает `base_score` и `score` с учётом события и добавляет поле `"event"` (объект события или `null`), в `districts[].before` уже учтено событие; `optimize` ищет наборы в уменьшенном бюджете.

AI-аким:
- `POST /api/agent` принимает `{"goal": str | null, "event_id": str | null}` и возвращает `{"decisions": [...], "simulation": {...}, "steps": [{"action": "validate" | "simulate", "decisions": [...], "summary": str}], "explanation": str, "optimizer_score": float | null, "source": "ai" | "fallback"}`.
- Агент использует OpenAI function calling с инструментами `list_measures`, `validate_plan(decisions)` и `simulate_plan(decisions)`; инструменты проверки и симуляции передают текущий `event_id` движку. `list_measures` возвращает фактический доступный `budget` и `event` (объект события или `null`).
- За один запуск допускается не более 8 вызовов инструментов. Итоговый набор всегда повторно проверяется через `validate` и `simulate`; если он невалиден, возвращается лучший валидный набор из проверенных.
- Числа в объяснении AI сверяются с результатами инструментов; при неподтверждённых числах выполняется одна попытка исправления, затем fallback.
- Без `OPENAI_API_KEY` или при ошибке AI возвращается лучший набор из `optimize(top=1, event_id)` с шаблонным объяснением, `source` равен `"fallback"`.
- Неизвестный `event_id` возвращает HTTP 422 с русским сообщением.

API (Агент 2) — новое:
- `GET /api/events` → `list_events()`
- необязательное поле `"event_id"` в теле `/api/validate`, `/api/simulate`, `/api/explain` и у каждого сценария в `/api/compare`
- параметр `event_id` в `GET /api/optimize?top=5&event_id=EV1`
- неизвестный `event_id` → 422 с текстом ошибки из `ValueError`

API (Агент 2):
- `GET /api/state` → бюджет, районы с базовыми оценками, меры, веса, base_score
- `POST /api/validate` `{"decisions": [...]}` → результат validate
- `POST /api/simulate` `{"decisions": [...]}` → результат simulate; невалидно → 422 `{"detail": {"valid": false, "errors": [...]}}`
- `POST /api/explain` `{"decisions": [...]}` → `{"simulation": {...}, "analysis": {"summary": str, "strengths": [str], "risks": [str], "consequences": [str], "tradeoffs": [str], "recommendations": [{"text": str, "replace": {"from": {"measure_id": str, "district": str | null}, "to": {"measure_id": str, "district": str | null}}, "score": float, "delta_score": float}]}, "source": "ai" | "fallback"}`
- `POST /api/compare` `{"scenarios": [{"name": str, "decisions": [...]}]}` → `{"results": [...], "analysis": str, "source": "ai" | "fallback"}`
- Невалидный набор в `/api/explain` возвращает 422 `{"detail": {"valid": false, "errors": [...]}}`; в `/api/compare` внутри `detail` дополнительно передаётся `"scenario": str`. `/api/validate` возвращает результат проверки с HTTP 200, включая невалидные наборы.
- `analysis.recommendations` формируется движком подбора замен после AI-анализа; `score` — Score после замены, `delta_score` — прирост относительно текущего плана.
- `GET /api/optimize?top=5` → результат optimize
- `/` отдаёт `web/index.html`, статика из `web/`

## Правила кода

## Правила git (обязательно)
1. Перед началом каждого нового файла выполни `git pull --rebase --autostash`, чтобы видеть актуальный код соседей.
2. Коммить сразу, как только закончен хотя бы один файл целиком и проходят тесты; готовая работа не должна лежать незакоммиченной дольше 5 минут. Незаконченные файлы не коммить.
3. Перед каждым коммитом:
    - выполни `git config user.name` и `git config user.email` и покажи пользователю автора;
    - выполни `git status` и убедись, что `.env` не попадает в коммит;
    - покажи список файлов и сообщение коммита и спроси пользователя «Коммитить?». Без ответа «да» не коммить.
4. Добавляй только свои файлы поимённо: `git add engine/scoring.py`. Никогда `git add .` или `git add -A`.
5. Сообщения в формате conventional commits на английском: `feat(engine): add score calculation`.
6. После коммита: `git pull --rebase --autostash`, затем `git push`.
7. Если push отклонён, повтори `git pull --rebase --autostash` и `git push`.
8. При конфликте: выполни `git status`, покажи пользователю конфликтующие файлы и спроси, что делать. Сам не разрешай конфликты в чужих файлах; конфликт в своём файле разреши, сохранив изменения обеих сторон, затем `git add <файл>` и `git rebase --continue`.
9. Никогда не делай `git push --force`, `git reset --hard`, не переписывай историю, не меняй git config.
10. Агенты Codex в песочнице не могут писать в `.git`: они не выполняют git-команды, а показывают пользователю список файлов и сообщение коммита, git выполняет человек.
